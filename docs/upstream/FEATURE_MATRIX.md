## C. 高危冲突区（必须逐项设计，不可直接合并）

| 区域 | 冲突本质 | 结论 |
|---|---|---|
| **Phone Use vs Device Tools** | 两套屏幕自动化执行器会争抢无障碍服务；权限、工具 Schema、操作队列、生命周期均不同 | 先做架构对照，**设计统一调度层**，底层复用 GMYSJ 执行器 |
| **Tool Calling 协议** | 官方 `e10e104` 把生成循环/审批协议迁到 `ai` 模块 `agent` 包，并修了混合审批、中途停止丢工具结果 | GMYSJ 有 91 个工具 + Sub-Agent 调度，**必须用真实调用链验证** |
| **Memory 数据** | 官方 3.0.0 改为文件化记忆库 | 先备份、幂等迁移、验证多助手隔离 |
| **上下文压缩** | 官方改「插入总结不删历史」 | 必须区分「聊天记录」与「Agent 长任务状态」 |
| **Workspace** | 官方加 SSH / 后台命令 / 共享挂载 | 必须兼容 GMYSJ 工作区目录、任务 ID、会话 |
| **UI 全改版** | 3.0.0 几乎重写所有页面 | 保留 GMYSJ Agent 控制台/工具/Workflow/Shizuku/Telegram/Doctor 入口 |
